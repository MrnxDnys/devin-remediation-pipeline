# Knowledge: Apache Superset remediation context

> Add to Devin as Knowledge (applies across all sessions on this repo). Source of truth here.

- **Repo:** `MrnxDnys/superset` (fork of `apache/superset`). Default branch: `master`.
- **Python dependencies:** pinned in `requirements/base.txt` and `requirements/development.txt`,
  generated by `uv pip compile` from the matching `*.in` files. For a single bump, edit the
  pinned `.txt` directly (or the `.in` then recompile). **Never touch `-e ./superset-core`.**
- **Frontend dependencies:** `superset-frontend/package.json` + `package-lock.json` (npm).
  Update the lock for one package with `npm install <pkg>@<ver> --package-lock-only` — do not
  run a full install or regenerate the whole lockfile.
- **Tests:** backend is pytest — run the narrowest relevant path (e.g.
  `pytest tests/unit_tests/<area>`), not the whole suite, to conserve ACUs. Frontend is jest
  (`npm run test` inside `superset-frontend`). Pick the tests that exercise the changed package.
- **Conventions:** minimal diffs; one concern per PR; every PR references its tracking issue;
  never merge — a human approves.
- **Version policy:** upgrade to the lowest version that clears the advisory, unless that
  version is yanked or itself vulnerable; then go to the next safe one.
- **Escalation:** if the fix needs a major/breaking upgrade that ripples across the codebase,
  stop and hand back to a human rather than attempting a large change.
